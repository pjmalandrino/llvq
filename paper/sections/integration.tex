\section{End-to-End Integration, and a Finding About the Reference Engine}
\label{sec:integration}

A kernel benchmark is not a serving number. This section takes the
\textsc{Planes14} kernel into a full autoregressive decode loop (greedy,
Qwen3-4B, single L40S) and attributes where the time actually goes.

\textbf{Setup.} The serving stack is \texttt{candle}~0.9.2
\citep{candle2023}, a widely used Rust inference engine, with our fused
kernel replacing the 252 linear projections. Weights are stored in the
incoherence-rotated basis required by the quantizer, so activations pass
through a dedicated rotation kernel (verified bit-exact on device) before
each projection. The embedding table (9.7\% of the model, untouched by
the 2-bit format) is stored int8 with per-group scales and offsets
(groups of 64), a change measured to be free on both evaluation metrics. Correctness gate: the
fused and dense engines emit identical greedy tokens until a
tie-break-level divergence (token 89), on top of the row-level f64
verification of \S\ref{sec:decoder}.

\textbf{The finding.} Table~\ref{tab:phases} shows the reference engine
spending 26.7~ms per token in the output head, twice the cost of all 36
transformer blocks. The cause is in the engine's source: for this matmul
shape, \texttt{candle}~0.9.2 takes a
$\texttt{broadcast\_matmul}\to\texttt{contiguous()}$ path that materializes
a 778~MB transposed copy of the vocabulary matrix \emph{on every token}
(the file carries its own \texttt{TODO:\ Avoid concretising} at the site,
\texttt{tensor.rs:1550}). Replacing the head with an int8 kernel that reads
its 413~MB in place collapses the phase from 25.9 to 0.6~ms. The copy
scales with the vocabulary projection: on the 8B (hidden size 4096, untied
head) it is 1.24~GB per token, and the same replacement doubles
end-to-end throughput there (34.4 to 69.3~tok/s). We believe this finding is of
independent interest to \texttt{candle} users: it taxes every model served
through this path, quantized or not.

\textbf{The double formulation.} End-to-end, the fused engine reaches
88.4~tok/s against the dense engine's 43.5, a factor of $2.03\times$.
Honesty requires splitting that number, because much of it is the head fix,
which a dense engine could adopt too. We do not derive the split from the
fenced phases: synchronization serializes work the real decode overlaps,
so phase sums attribute time but do not compose into a throughput. Instead
we report the measured lower bound: with the defective f16 head path held
identical in both arms, the fused engine gains $1.12\times$ on the 4B
(48.7 versus 43.5~tok/s) and $1.29\times$ on the 8B (34.4 versus 26.6).
Both numbers understate the kernel, whose own phase runs $1.27\times$
faster (13.3 to 10.4~ms across the transformer blocks) and whose projection
benchmark runs $2.14\times$ over FP16; the giant head phase dilutes them.
We report both formulations, always together: $2.03\times$ against the
engine as everyone runs it today, at least $1.12\times$ against that
engine with its copy fixed.
