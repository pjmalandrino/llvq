WHY ASK THIS AT ALL
-------------------
Stage 5's gate is "a clean environment runs pip install then from_pretrained and
reproduces the tokens", and stage 6's in-tree guide requires the package to exist.
Every measurement of stages 0 to 4 ran from the working tree through our own
scripts. So nobody had ever asked what a stranger gets.

WHAT IT FOUND, BEFORE IT MEASURED ANYTHING
------------------------------------------
`import llvqhf` REGISTERED NOTHING. `__init__.py` imported `tetra` and `reader`
and never `quantizer`, so `register_quantizer` never ran. Our 41 tests and our
six journals are all sound because every script of this package imports
`.quantizer` by hand: `gentokens.py` line 23 carries the comment "(registers
llvq)". Four stages of measurement passed over this.

The failure is SOFT, which is the worse half. transformers does not raise:

  [transformers] Unknown quantization type, got llvq - supported types are:
  [...]. Hence, we will skip the quantization.

It then loads the model as if it were dense, reports every record as UNEXPECTED
and every dense weight as MISSING, and raises fifty lines later:

  RuntimeError: You set `ignore_mismatched_sizes` to `False`, thus raising an
  error.

A reviewer seeing that would conclude the checkpoint is broken, and would have no
reason to think otherwise.

Fixed in `llvqhf/__init__.py`: the package imports `.quantizer`, guarded by
`ImportError` because transformers and torch are an optional extra and
`PackedModel` must stay readable with numpy and safetensors alone.
`tests/test_registration.py` holds it, in a FRESH interpreter by subprocess,
since in ours an earlier test has already imported the module and the question
cannot be asked. Mutant posted and caught: registration removed, 1 site asserted,
the test falls; restored, it passes. 41 tests green.

THE SECOND GAP, CLOSED ON 2026-10-02
------------------------------------
`tests/fixtures/mini` is a coherent one-layer Qwen3 of 148 KB, written by
`the_mini_fixture_describes_a_whole_qwen3_layer` in `llvq-llm/tests/hfpack.rs`,
and `tests/test_load.py` calls `from_pretrained` on it. 46 tests pass, 41 before.
The `tiny` fixture below is untouched: its shapes are asserted by name in the
packer test and read by five Python test files, and it does its own job.

  hidden_size 136, head_dim 32, 4 q heads, 2 kv heads, intermediate 256, vocab 64
  q_proj     128 by 136  tetra      5 blocks, tail 16, rotation odd part 17
  k_proj      64 by 136  tetra
  v_proj      64 by 136  tetra
  o_proj     136 by 128  tetra      5 blocks, tail 8, rotation odd part 1
  gate_proj  256 by 136  tetra
  up_proj    256 by 136  tetra
  down_proj  136 by 256  int4 g128  2 whole groups
  embedding   64 by 136  int4 g64   2 groups and a partial third
  5 norms     136, 136, 32, 32, 136  f16

Not one of those numbers is free. 136 = 17 x 8, so the rotation
`Q = (Q_odd (x) H_m) D` has an odd part of 17 and `Q_odd` is a real matrix; a
power-of-two width gives the trivial 1 by 1, which `o_proj` at `d_in` 128 then
covers, so both paths run. 136 = 5x24 + 16 and 128 = 5x24 + 8, so two different
non-empty tails. int4 sits on `down_proj` alone because the test helper takes
`gpr = d_in / 128` by integer division and 136 is not a whole number of groups;
the FORMAT itself carries a partial group, which the embedding at group 64 proves,
since 136 is two groups and a third of 8 columns.

A FORWARD PASS THAT RUNS PROVES NOTHING, AND THIS IS MEASURED. The first version
of `test_load.py` left `import llvqhf` out of the module level. Run alone, it
loaded the fixture with the method unregistered: transformers skipped the
quantization, reinitialized every dense weight it reported MISSING, and the
forward pass passed on random numbers. Three of the five tests passed, including
the shapes and the forward. The gate is `missing_keys` and `unexpected_keys`.

Mutant posted and caught: the module-level import removed, 1 site asserted, two
of the five tests fall and the other three do not. Dropping a norm from the
fixture is caught upstream instead, by the packer test's `raw_tensors == 6`.

What the fixture cannot say: the weights are random, so no logit value means
anything, and nothing here asserts on one. It covers the dense CPU path only; the
Metal and CUDA arms need a GPU and are not in any test.

THE GAP AS IT WAS, 2026-10-01
-----------------------------
The 4 KB fixture is not a loadable model. Its config.json describes a Qwen3 of
hidden_size 96 while its records are 4 by 88, so `from_pretrained` refuses by
name: "model.layers.0.self_attn.q_proj is 4096 by 96, the record is 4 by 88". It
was written for unit tests that read tensors directly and it does that job.

The consequence is that the package has NO small object anyone can load end to
end. A reviewer must fetch 1.4 GB to see it work, and the test suite cannot cover
`from_pretrained` at all without that file. For an in-tree PR this is the kind of
thing a maintainer asks for first. Fixing it means changing the Rust fixture
writer, and it is not done.
