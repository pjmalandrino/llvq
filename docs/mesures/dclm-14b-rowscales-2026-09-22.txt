THE GAUGE SAID NO, AND IT WAS WRONG
------------------------------------
`llvqtune` exited 1 because `Outcome.improved` (loop.py:79-95) compares the mean
loss of the last third with the first: 0.1559 against 0.1531, +1.8 %. By
eighths, 0.1522 0.1537 0.1555 0.1656 0.1542 0.1529 0.1590 0.1561, +2.6 %.

The gauge's own docstring says it is only meaningful on a repeated batch, and
the DCLM corpus streams (E1). The census settles it: a resolved +1.67 pp from
a run the gauge called unimproved. The stamped row would have discarded a real
gain. What the flat curve does say is that the gain arrived early: the loss
fell from 0.2229 at step 1 to about 0.15 within the first eighth and stayed
there. Whether a shorter run would have given the same G is not measured.

**Consequence for the tool, not applied here:** `improved` cannot gate a
streaming run. Either the gate runs on a held-out fixed batch, or the exit code
stops reading it. Neither is decided.
