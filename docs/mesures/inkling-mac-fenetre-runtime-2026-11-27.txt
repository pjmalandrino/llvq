  against 127.40 s [127.31, 127.42] under `full`, medians of three alternated pairs, cold, a fresh server each,

  `inkrun` read x0.855 [0.854, 0.856] for the same arm (inkling-mac-fenetre-2026-11-27): the gain reaches the server
  whole.

  the committed build, token for token, and prints the same load lines (H-i). The key of a prefix file under `full`
  serializes to the bytes it had before the field (unit test).

  line of 46 (the reasoning says "based on policy." where `full` says "based on policy text."); on the short prompt
  its 48 tokens are `full`'s. Its own answers repeat across four servers.
  A prefix file of one arm is not loaded under the other (H-iv), and `narrow` is refused by name on the CPU backend
  and on a Qwen3 of the store.

  value exits naming the switch (`--attn-window "wide": full or narrow`). `llvq serve --help` is the committed
  build's, byte for byte but for the binary's name (help-before.txt, help-after.txt).

  like `prefix::set_options`, and `window_scores_for(arm, backend, fused)`: `full` never turns the scores on,
