LES CONTRÔLES DU §4
-------------------
  1. Permutation : `perm(0x00149f) == 0x0000ff` etc. — remplacé dans le code
     par le contrôle discriminant (ordre trio → 3/3 supports dans le code ;
     identité et 5 ordres stridés → 0/15), parce que l'assertion littérale
     est vraie par construction quel que soit TRIO. Test de f1.rs, vert.
  2. Appartenance : tout point gagnant, permutation défaite, passe
     `llvq_core::Leech::contains`. Test de f1.rs, vert, zéro exception.
  3. Rangs par MOTIF : le DP de comptage est indexé par motif ; il coïncide
     avec la force brute bac par bac et sur chaque point de la coquille de
     bord. Tests de f1.rs, verts.
  4. Bijection : les covolumes 2¹⁶ · 2¹² · 2¹⁶ / 256 = 2³⁶ = det(√8·Λ₂₄),
     confirmés par comptage de points et non affirmés. Test de f1.rs, vert.
  5. Suboptimalité de l'encodeur : le §4.5 demandait « le même encodeur à
     balayage sur la boule-12 ». Ce n'est PAS ce qui a été fait — écart É1.
     À la place : (a) l'encodeur de section est comparé à la recherche
     exhaustive sur la région (llvq-bench/examples/f1enc.rs, 400 cibles par
     section, graine 0x5f1b_2026_0904) et rend l'optimum EXACT dans 100 % des
     cas sur les trois sections (rejoué le 2026-09-05, même résultat) ;
     (b) le balayage d'échelle ne produit que des candidats réalisables, donc
     il ne peut que SOUS-estimer F1 — le biais est à sens unique, contre F1.
     Le témoin boule-12 est calculé par la réduction en coquilles exacte
     (m ≤ 12) et non par un encodeur à balayage, donc il n'est pas affecté.
