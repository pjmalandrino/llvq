  prompt after 20.33 s, median of 3 [20.31, 20.39], against 140.99 s read cold (*measured*). The answer at temperature

WHAT CHANGED
  B. `long_prompt` (llvq-runtime/src/inkling.rs) answers `BiasOnHost` for the CPU, whatever the stack: every CPU load
  is `experts_cpu::load_served`, which sets the pieces of 512, the score rows of 128 and the slack of 1,024 itself
  (llvq-llm/src/inkling/experts_cpu.rs), and the model, not the runtime, cuts the prompt (`Inkling::forward_pieces`).
  A compile-time assertion holds the runtime's three values equal to the CPU load's. A CPU build has no bias kernel
  (`attn_bias` is compiled for CUDA and Metal only), so the bias is `layers::score_bias_host` and the key's `bias`
  field, `host`, says what runs. The key names the stack `cpu` and the backend `cpu`; a CPU file is never loaded on
  Metal. `prefix_on_by_default` is now true on Metal and the CPU.
  C. A held segment that ended a prompt keeps the logits of its last position as `pick` reads them (flat f32 on the
  host, 200,058 values, 0.8 MB). When the whole prompt of a request is held and its last segment has them, the server
  goes back to that segment's mark and samples from them, with no feed. Without them, or when the rollback is refused
  (a bounded sliding slot past its slack), it reads as before.

THE QWEN3 ENGINE (llvq-runtime/src/engine.rs, read, not changed)
  It does not have the defect. `Session::reuse_prefix` keeps the common prefix up to the prompt's length minus one,
  so a prompt sent again reads one token, not a segment. Kept logits would save that one forward and nothing more.

WHAT THE READING DOES NOT SAY
  Nothing about x86: the CPU numbers are this Mac's. Nothing about CUDA, still off by default and type-checked only.
  The CPU warm number is for a block just over 2,048 tokens; a longer block saves more, since the cost after b stays
  under 512 tokens plus the user message. C-ii timed one server an arm; the before and after servers did not
  alternate.
