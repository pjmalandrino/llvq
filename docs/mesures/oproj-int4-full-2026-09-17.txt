THE BUDGET, CORRECTED
----------------------
The prereg and the exploration journal both said the arm fits because the model
goes 2.7645 -> 2.9599 "under b_max = 3.00". Those are whole-model b/param;
b_max is kernel b/weight. Wrong comparison (E4). Redone in the right unit
(computed, 3,633,315,840 projection weights, Tetra 2.1498, int4 g128 4.250):

  int4 served natively        2.2044 -> 2.4226 kernel b/weight   under 3.00
  int4 dequantized to f16     2.5095 -> 3.9485 kernel b/weight   OVER 3.00

The served Q5 measures 0.97 GB of projections on card, which matches the native
path (1.001 GB computed) and not the dequantized one (1.140). So the arm fits IF
o_proj is served by the native int4 kernel, as v_proj already is. That kernel
has run on v_proj's shape, 1024 x 2560, and never on o_proj's, 2560 x 4096.

In whole-model b/param, the unit hard rule 6 asks for in comparisons: 2.7645 ->
2.9599 (computed). That figure stands; only its comparison to b_max was wrong.
