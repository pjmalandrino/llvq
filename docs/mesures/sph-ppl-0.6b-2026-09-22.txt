WHAT IT MEANS
--------------
The paper's Spherical GPTQ, applied to Tetra as the retraction of the error
feedback alone (stored block on the gain grid, residual against q.|w|/|q|), is
not a gain. It is the largest single degradation this protocol has recorded on
a one-word change: tetrapost cost +4.0 %, design C x1.99 on the full solve, this
costs +31.9 %.

The named opponent of the prereg §2 won: with a two-level gain code the columns
after a block must be compensated for the radial error the file actually
carries. Chasing that error is not the "radial drift" the paper kills; leaving
it unchased is. What the paper's loop does at 0 gain bits, where the magnitude
is a free float until the closed-form solve, does not transfer to a coded gain.

The reading that survives is the one ETAT §4 already states: Eq. 17 is a no-op
under a coded gain, and the shipped loop is the right loop for that gain. The
+1.9 pp the docs carried as "Spherical GPTQ, Table 9, noise / 1.30"
(tetranu-rowscales-2026-09-19.txt) is not available to this format by this
route.

ADDENDUM — THE MECHANISM, MEASURED (2026-09-22, same day, $0)
--------------------------------------------------------------------------------
The section above says the mechanism was not measured. It is now, on a Gaussian
source, by `llvq-bench/examples/sphgeom.rs`. Raw: -brut/sphgeom.txt, two seeds.
Decisional for nothing: the endpoint is already read.

Write u for the coded direction, t = <x,u> = |x| cos(theta), g^ for the magnitude
the file stores. The two residuals the loop can be handed are

  published   x - g^.u        radial component  t - g^
  retracted   x - |x|.u       radial component  t - |x|

and their difference is (|x| - g^).u, purely radial. It is IDENTICALLY ZERO when
the code stores the block's own norm, which is what a 0-gain-bit direction code
does by construction. Pinned in the suite: on `LeechDirection` the flag moves the
layer by <= 1e-12 (`norm_preserving_direction_code_makes_the_flag_inert`).

Under Tetra it is not zero (*measured*, 20,000 Gaussian blocks, two seeds):

  g^/|x|    mean 1.00684   sd 0.09200    p1 0.8241   p50 0.9999   p99 1.2969
  cos theta mean 0.96080   sd 0.00756
  gap energy / stored error energy        0.0872
  the retracted residual carries -7.96 % of the true error energy

Seed 777 replays it: 1.00768 / 0.09300 / 0.0874.

So the bias is small, 0.7 %, and the SPREAD is 9.2 %. What `sph` hides from the
correction is not a systematic offset a scalar could repair later. It is a
per-block random quantity of 9.2 %, one per block, 85 blocks a row, never handed
to anyone. On real compensated blocks the same ratio reads 0.99336 as a mean
(*measured*, tetrapost-ppl-0.6b-2026-09-15), the other side of 1 and the same
order; the Gaussian source is what is priced here, not a GPTQ residue.

THE PAPER'S TABLE 9 CANNOT ATTRIBUTE ITS GAP TO THE RETRACTION
---------------------------------------------------------------
Read down the Code column of Table 9 as transcribed in `llvq-paper-notes.md`:
every `GPTQ` row carries the Euclidean search metric and every `Spherical GPTQ`
row carries the angular one.

  LLVQ [spherical shaping]                GPTQ              (default: euclidean)
  LLVQ [sph. shaping] (forced ang.)       Spherical GPTQ
  LLVQ [shape-gain 2 bit] (forced eucl.)  GPTQ
  LLVQ [shape-gain 2 bit]                 Spherical GPTQ    (default: angular)

The search metric and the correction move together in all six pairs, so the
+1.9 pp this repository has been quoting (34.1 -> 36.0, shape-gain with Input
rotation) prices BOTH changes, not the retraction alone. Tetra's encoder is
already the angular one (cos theta 0.9608, measured above), so our `sph` arm
changed only the second half of that bundle. That is why our arm and their
column are not the same experiment, and it is a second reason not to expect
their number here.

This does not say the paper is wrong. It says Table 9 does not isolate what the
docs read off it. `ROADMAP-QUALITY` row 3 and the "Spherical GPTQ +1.90" line of
`tetranu-rowscales-2026-09-19.txt` both rest on that reading.

CORRECTION TO THE ADDENDUM, SAME DAY
-------------------------------------
Two things the addendum above gets wrong or leaves implicit. Both were found by
measuring rather than by reasoning, which is why they are here.

**"Radial drift" does not separate the two codes by its spread.** The contrast
arm was run: spherical shaping, the ball code the paper's 191.90 belongs to,
beta* = 0.3500 on the same blocks. Its ‖ŵ‖/‖x‖ reads mean 0.98069, sd 0.08332
(seed 777: 0.97438 / 0.08638) against Tetra's 1.00684 / 0.09200. The ball code's
radial spread is NOT wider than ours; it is slightly narrower. Any explanation
of the form "their code drifts and ours does not" is refuted on this source. The
paper's 191.90 is a no-rotation number and whatever it measures, it is not a
larger radial spread at a fitted scale on a homogeneous source.

**What actually separates them is WHERE the magnitude is decided.** Algorithm 3
line 5 reads `W̃_{:,Q} <- (‖W̃‖/‖Q(W̃)‖)·Q(W̃)`: it assigns to the STORED weights.
The paper's retraction improves the reconstruction by restoring the exact norm,
and the honest feedback is a consequence of that, not a separate lever. It is
paid for, in a free float per block (0.67 b/weight) or by deferring the decision
to the closed-form solve after the loop.

So there are three designs, not two, and `sph` is the third:

  design        stored          propagated against   rate         coherent
  A, published  ĝ·u             ĝ·u                  48 bits      yes
  B, Eq. 17     ‖x‖·u           ‖x‖·u                47+16 bits   yes
  sph           ĝ·u             ‖x‖·u                48 bits      NO

`sph` was an attempt to take B's feedback without B's bill. The result says the
bill is the lever: there is no feedback benefit to collect separately, because a
residual is only honest if it describes what is stored. B is design B of
`docs/archive/retraction-et-gain.md`, and it was already rejected on rate in
July 2026, not on quality.
