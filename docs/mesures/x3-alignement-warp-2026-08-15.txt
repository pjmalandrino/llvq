CE QUE LE LAYOUT PROMET
  `llvq-artifact/src/e1c.rs`, en tête : « Because that is the CUDA warp. The
  transposition puts bit `l` of a word at lane `l`: every lane of the warp
  reads the SAME word address, so the load is a broadcast out of L1 rather
  than 32 scattered strided reads. That is the whole argument for the layout. »

CE QUE LA DÉCOMPOSITION IMPOSE
  Le matvec servi met un warp par LIGNE de sortie (`planes.cu:38-52`) :
    row  = (blockIdx.x·blockDim.x + threadIdx.x) >> 5
    b0r  = row · nblocks
    for (j = jlo + lane; j < jhi; j += 32)  → bloc global b0r + j
  Le groupe E1c est 32 indices de blocs GLOBAUX consécutifs. La lane `l` d'un
  warp traite donc le rang de groupe

    (row·nblocks + jlo + lane) mod 32  =  (row·nblocks + lane) mod 32

  puisque `jlo` est un multiple de 32. C'est une ROTATION de 0..31 par
  `row·nblocks mod 32`. Elle vaut zéro — donc les 32 lanes tombent dans UN seul
  groupe — si et seulement si `nblocks ≡ 0 (mod 32)`.

CE QUE COÛTERAIT DE L'ALIGNER                                        [calculé]

  Le seul remède compatible avec le matvec servi est de bourrer chaque LIGNE
  à un multiple de 32 blocs. Il n'y en a pas d'autre, et il faut dire pourquoi :

  · un groupe partiel ne coûte pas moins qu'un groupe plein — la région
    transposée est 24·(1+plans) mots QUELLE QUE SOIT la lane occupée, donc un
    groupe de 10 blocs coûte le prix de 32 ;
  · réordonner les blocs pour que les groupes tombent sur les warps revient au
    même bourrage : le warp lit 32 j consécutifs D'UNE LIGNE, donc le groupe
    doit être 32 j consécutifs d'une ligne, donc les fins de ligne se bourrent ;
  · faire lire un groupe entier à un warp casserait l'accumulation par ligne —
    un groupe enjambe les lignes, les lanes accumuleraient dans des sorties
    différentes. Ce n'est plus porter un layout, c'est écrire un autre matvec.

  bourrage par forme :
    106 blocs/ligne → 128 : +20,75 %   (97 689 600 blocs réels)
    170 blocs/ligne → 192 : +12,94 %   (15 667 200)
    405 blocs/ligne → 416 :  +2,72 %   (37 324 800)
  global : 150 681 600 → 173 998 080 blocs, +15,47 %
