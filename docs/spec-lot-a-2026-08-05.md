## A1 — Premier passage sur carte (~0,1-0,5 $ au total)

1. **Local d'abord** : `cargo test --release -- --include-ignored` (~45 s,
   tout vert) et `cargo clippy --all-targets` (zéro warning). Puis
   `git checkout main && git merge --ff-only noyau-cuda` — on repart de
   `main`, comme convenu.
2. **Publier l'image** : `uv run ops/run.py publish <user>/llvq-runner-cuda
   --cuda`. 40-70 min, 0 $, prévoir 2 tentatives (précédent documenté). Le
   builder n'a pas de GPU — c'est pour ça que `CUDA_COMPUTE_CAP` est figée.
3. **Gate absolu — l'oracle** : `uv run ops/run.py oracle --image …` →
   doit rendre `max |Δhidden| = 0.000e0`, exactement comme les fois
   précédentes. 42 s, ~1 centime. Rouge → on s'arrête là et on diagnostique.
4. **La rotation sur carte** : dérouler `rotation_matches_rust` (ou
   `rotbench`) sur la carte — le noyau a 15 mutants tués côté CPU mais n'a
   **jamais** tourné sur NVIDIA. Bit-exactitude exigée.
5. **`fusedrun` sur L40S** : `fusedrun <scellé> 128`. Le scellé de référence
   est `~/llvq-q4b.llvq` (980 790 202 o) — vérifier comment la campagne
   prévue le met à disposition du job (repo HF + cache C5 ; sans C5, +26 min
   de re-téléchargement). Lire dans l'ordre : (a) position de la première
   divergence de tokens — 1 à ~5 = bug, tardive = tie-break à documenter ;
   (b) octets device des deux bras — le chiffre de thèse ; (c) tok/s des
   deux bras.
6. **Lecture du tok/s** : attendu ~51-53 tok/s fusé contre ~42,8 dense
   (×1,19-1,23, bornes des mémoires projet). ⚠️ Le « 48 % d'overhead » est
   une soustraction jamais confirmée par chronomètres : si le fusé sort SOUS
   l'attendu, **instrumenter avant de conclure** (t_submit + events par
   phase, cf. §5 de l'audit du 2026-08-05) — ne pas itérer à l'aveugle.

**Critères de sortie A1** : oracle exact · rotation bit-exacte sur carte ·
divergence de tokens absente ou tardive et documentée · octets device
rapportés · tok/s fusé ≥ dense. Consigner les millisecondes brutes dans
`docs/mesures/` comme d'habitude.

## A2 — Le cache KV recopié (petit, dans la foulée)

`model.rs` (~l. 422) : `repeat_kv(...).contiguous()` **recopie le cache KV
4× par bloc et par token** (GQA 8→32 têtes). Piste : éviter la
matérialisation (matmul broadcast de candle, ou reshape groupé
`[b, 8, 4, t, d]`). Gates : sorties identiques à 1e-6 près sur le test
existant, et A/B de temps par token **bras entrelacés dans le même job** —
une seule variable. Si candle l'impose structurellement, le documenter et
passer — ce n'est pas un bloqueur.

## A3 — CUDA Graph, en deux étages

**(a) Au banc d'abord** — c'est la « condition de publication » de l'audit :
tout gain mesuré à travers 252 lancements est dilué par `252·g`, et `g` doit
être connu. Piège identifié dans le code : `Cuda::new` prend
`ctx.default_stream()` — le **NULL stream legacy**, dont la capture est
refusée par le driver (`CUDA_ERROR_STREAM_CAPTURE_UNSUPPORTED`). Le passage
à `ctx.new_stream()` change l'objet mesuré → **contrôle à trois bras dans le
même job : legacy / new_stream / new_stream+graph** (cudarc 0.19.8 :
`begin_capture`/`end_capture`/`launch`, ~40 lignes). Règle du dépôt : les
deux bras ou aucun.

**(b) Dans `fusedrun` ensuite, et seulement si (a) est concluant** — piège
structurel : le cache KV croît par `Tensor::cat` (formes dynamiques à chaque
token), incompatible avec un graph statique. Il faut préallouer + `narrow`
(chantier qui rejoint A2). Scoper après le verdict de (a), ne pas
l'improviser.

- Les réglages noyau **gelés par l'audit et les jobs du 2026-08-05** ne se
  rouvrent pas : bancs/padding (réfuté), gather `tab` (clos), table en
