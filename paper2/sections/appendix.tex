\paragraph{Defects found by the served runs.} The first served runs of the
three sealed files failed on two defects in our engine, before producing any
number. First, projections that read the same input form a group. A group with
no rotation took a code path that sends all prompt rows to the matrix-vector
product at once. That is correct for a dense matrix and wrong for the int4
kernel, which takes one row. A lone int4 \texttt{o\_proj} or
\texttt{down\_proj} forms such a group. An int4 \texttt{v\_proj} never does,
since its group also holds the rotated $q$ and $k$. Second, the int4 kernel was
capped at the
default 48~KiB of shared memory. A 14B \texttt{down\_proj} needs more. We
fixed, tested and type-checked both before the runs behind the speeds in
Table~\ref{tab:main}. Neither defect affects an MMLU number, because MMLU is
scored on the dense reconstruction, which does not run the kernel.

\paragraph{A corrected IQ2\_XXS rate.} An earlier version of our 4B table gave
IQ2\_XXS 2.4967 bits per parameter. That is the rate of a different IQ2\_XXS
file, published by a third party and never scored here. The file we score is
our own build: 1{,}246{,}620{,}832 bytes, or 2.479 bits per parameter.

first eight hex digits of their SHA-256:

\item \nolinkurl{qwen3-4b-sealed.bin}, \texttt{886391a8};
\item \nolinkurl{qwen3-8b-sealed-B.bin}, \texttt{7bdb9a55};

\end{itemize}
Each file has a served configuration in \nolinkurl{configs/}, named after its
size; the commands below use the 4B one. On an NVIDIA GPU:

{\footnotesize
\begin{verbatim}
# tok/s and GB at the served flags, 256 tokens, against the dense arm
LLVQ_FUSED_LAYOUT=tetra48 LLVQ_ROT_SHARE=1 LLVQ_FUSE=0 LLVQ_KV=f16 \
  LLVQ_EMBED=q4 cargo run --release -p llvq-llm --features cuda \
  --bin fusedrun -- <file> 256
# MMLU on the full test set, then a paired comparison of two dumps
LLVQ_MMLU_ALLOC=flat LLVQ_MMLU_DUMP=<dump> cargo run --release \
  -p llvq-llm --features cuda --bin mmlu -- <file> cuda
cargo run --release -p llvq-llm --bin mmlupair -- <A> <B> --no-fpc
# GSM8K through the served kernel, then a paired comparison
LLVQ_CONFIG=configs/qwen3-4b-tetra-e4.json LLVQ_GSM8K_DUMP=<dump> \
  cargo run --release -p llvq-llm --features cuda --bin gsm8k -- <file> cuda
cargo run --release -p llvq-llm --bin gsm8kpair -- <A> <B>
# bits per parameter over the whole model
cargo run --release -p llvq-bench --bin rtbits -- <file>
\end{verbatim}}

\noindent \texttt{mmlu} and \texttt{gsm8k} print a fingerprint of the prompts
they scored. Two scores compare only when their fingerprints match, and the
two pairing programs refuse dumps whose fingerprints differ.
