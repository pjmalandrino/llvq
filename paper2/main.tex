\begin{abstract}
\noindent
Quantizing weights on the Leech lattice gives good quality at two bits per
weight. But its codebook has $1.1\times10^{14}$ points, far too many for a
lookup table, so our earlier kernel expanded the codes when loading the model.
It then read 4.804 bits per weight from GPU memory for 2 bits of code. We
present \Tetra{}, a new codebook on the same lattice. Each block of 24 weights
still takes 48 bits. Most of these bits now index a 64-state trellis built
from the Golay code and one 16~KiB table used by every block. The kernel
decodes a block with six table loads inside the matrix-vector product and
reads 2.148 bits per weight. To build full models, we retrain one scale per
matrix row, store the matrices that lose the most accuracy as 4-bit integers,
and store the embedding tables in 4 bits to pay for them. The resulting
Qwen3-4B, 8B and 14B files hold 2.73, 2.70 and 2.73 bits per parameter over
the whole model. They score 63.37, 69.58 and 75.66 on the full MMLU test set
and generate 113.8, 95.0 and 57.2 tokens per second with 1.38, 2.76 and
5.04~GB of weights. That is 4.76, 4.21 and 2.46 MMLU points below 4-bit AWQ,
which needs 5.3 to 6.0 bits per parameter. At 4B our file scores 23.6 points
above llama.cpp's IQ2\_XXS (2.48 bits per parameter). All measurements use one
NVIDIA L40S GPU. Code, measurement logs and preregistered predictions are
public.
\end{abstract}
